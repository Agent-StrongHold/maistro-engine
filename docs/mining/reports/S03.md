### /home/user/stronghold/src/stronghold/security/auth_composite.py:1-52
**What**: Multi-provider auth combinator. Tries each provider in order; first success wins. Treats all exceptions uniformly (just continue to next).  
**Engine coverage checked**: `/home/user/maistro-engine/packages/maistro-core/src/maistro/security/auth_composite.py`  

**Gap severity**: MEDIUM  
**Product-agnostic?**: YES  

**Findings**:
- **Exception semantics refinement (Fix #13)**: Engine distinguishes three exception types:
  - `CredentialNotApplicable` — "not my format" → try next provider
  - `AuthError` — "valid format, rejected" → fail immediately (don't fall through)
  - Other exceptions → infrastructure failure → fail immediately (don't mask as auth miss)
- **Stronghold treats all exceptions as "not applicable"** (lines 43-45): Catches all exceptions and continues to next provider. This masks infrastructure failures (e.g., JWKS endpoint down) as auth miss, delaying detection of real problems.
- **Engine legacy ValueError handling** (Engine lines 54-58): Backwards-compat for old providers that raise ValueError; treats as CredentialNotApplicable. Stronghold has no migration path.
- **Error message**: Stronghold logs full error (line 50) then returns generic message (line 51). Engine logs categorized error (lines 61-66) with provider name and error type.

**Action**: Engine's exception semantics are superior — prevents infrastructure failures from being silently masked. Stronghold should adopt CredentialNotApplicable/AuthError distinction. **RECOMMEND for Stronghold backport**.  
**Effort**: M (requires auth provider interface update)
