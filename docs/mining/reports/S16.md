### /home/user/stronghold/src/stronghold/api/routes/chat.py:24-139
- **What:** OpenAI-compat `/v1/chat/completions` POST endpoint with structured Gate (Warden scan, strike tracking, clarifying questions). Returns JSON response or 400/403 security violations, 429 quota, 502 pipeline error.
- **Engine coverage checked:** 
  - maistro-server/api/chat_completions.py (lines 162-197)
  - hive-conductor/backend/routes/chat.py (lines 89-119)
- **Gap severity:** partial
- **Analysis:** Engine chat endpoint exists but is structurally weaker:
  1. **Missing Gate logic:** Engine has no Warden scan or strike tracking; no clarifying_questions flow.
  2. **Missing session_id validation:** Stronghold validates and scopes session_id to org/team/user (lines 47-55); engine has no session scoping in maistro-server.
  3. **Missing execution_mode:** Stronghold supports execution_mode ("best_effort", "persistent") from request body (line 41); not in engine.
  4. **Missing intent_hint:** Stronghold extracts intent_hint from body or maps "intent" field (line 42); engine chat_completions only uses request.model.
  5. **Auth integration:** Both validate auth, but Stronghold extracts headers for OpenWebUI user extraction (line 33); engine uses simpler RequireAuth.
  6. **Response format:** Stronghold returns full OpenAI format with `_gate` metadata on clarification (line 118-122); engine simpler ChatCompletionResponse.
  7. **Error envelopes:** Stronghold returns detailed error object with strike, flags, appeal_endpoint (lines 84-99); engine returns HTTPException.
- **Action:** partial port (Gate + session scoping missing; intent_hint + execution_mode useful but non-critical)
- **Effort:** M
- **Product-agnostic?:** Stronghold-owned (multi-tenant/org-scoped session, Gate is security-posture diff)
